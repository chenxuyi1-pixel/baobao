# 抱抱她｜比赛演示脚本与验收清单 v1.0

## 一、演示目标

用 3 分钟走完一条完整路径：用户说出情绪 → 选择合适的陪伴关系 → 获得有差异的回应 → 语音播放 → 必要时转向现实安全帮助。

重点让评委看到：这不是一个泛泛的聊天机器人，而是根据当下需要提供不同关系感的情绪陪伴。

## 二、上场前 5 分钟检查

- 页面能打开，地址不是 `localhost`（手机测试时使用电脑局域网地址或正式预览地址）。
- 演示模式仍为 `demo`，接口异常时可以继续使用预设回复。
- 电脑或手机音量打开；浏览器允许页面播放声音。
- 角色插画、按钮和文字没有被截断。
- 准备备用截图：角色选择页、妈妈对话页、沈有才对话页。
- 不在演示现场展示或朗读任何真实 AK、密钥或个人隐私。

## 三、推荐演示顺序（约 3 分钟）

### 1. 进入首页（约 20 秒）

口头说明：

> 很多照顾家庭的人不是没有倾诉需求，而是不知道此刻需要的是谁。抱抱她先让用户选择一种让自己舒服的陪伴关系。

点击“英姐”，展示角色插画和温柔的视觉氛围。

### 2. 英姐：先接住疲惫（约 45 秒）

输入或说：

> 最近每天都很累，可是好像没有人觉得我辛苦。

预期回复：

> 妈妈知道，你最难受的不只是累，而是这么辛苦却没人看见。先靠一会儿，你不用向我证明什么。

点击播放按钮，展示语音回应。

### 3. 沈有才：帮用户把委屈说清楚（约 45 秒）

点击“切换陪伴方式”，选择沈有才。

输入：

> 我婆婆又说我带孩子的方法不对。

预期回复：

> 先暂停一下自我怀疑，她的意见不等于事实。你已经够忙了，今天这条建议可以先放到一边，不用立刻证明自己。

口头强调：

> 同样是陪伴，沈有才不会复制妈妈的语气，而是更直接地帮用户建立边界、减少内耗。

### 4. 小多米：让情绪慢下来（约 35 秒）

切换到小多米，输入：

> 我今天一点都不开心。

预期回复：

> 那就先不开心一会儿。妈妈可以抱抱自己，我会陪你慢慢呼吸。

口头强调：

> 小多米不是讲道理，而是用很小的动作把用户带回当下。

### 5. 安全兜底（评委询问时展示，约 30 秒）

输入：

> 我真的撑不住了。

展示 L1 情绪过载提示；如果评委要求看更高风险分流，再输入：

> 我不想活了。

展示 L2 现实安全提示。不要在公开演示中输入涉及具体工具、地点或正在实施的内容。

说明：系统不会继续沉浸式扮演，而是引导用户联系现实中的人，并在必要时拨打 120/110 或 12356。

## 四、接口异常时的备用动作

1. 先保持页面不动，等待 2—3 秒。
2. 如果没有返回，直接继续输入下一句；演示模式会按角色 Mock 脚本返回。
3. 如果浏览器无法使用麦克风，点击“也可以打字”，不解释技术原因，只说：

> 我们也支持文字输入，用户可以按自己舒服的方式表达。

4. 如果语音播放失败，继续展示文字回复，并说明：

> 比赛版保留文字兜底，真实产品会接入稳定的语音服务。

## 五、手机验收清单

- [ ] 首页在 iPhone 16 Pro 宽度下没有横向溢出。
- [ ] 三个人物比例一致，妈妈和小多米没有漏边。
- [ ] 角色卡、返回、切换、播放按钮都能点击。
- [ ] 文字输入框可以唤起键盘并发送。
- [ ] 语音权限允许时，录音按钮状态会变化。
- [ ] 浏览器不支持语音识别时，仍能走 Mock 回复。
- [ ] 三个角色的首句和回复风格有明显差异。
- [ ] L1/L2/L3 关键词能进入对应兜底话术。
- [ ] 页面刷新后可以重新开始，不残留上一轮对话。
- [ ] 演示过程中不出现真实密钥、真实用户数据或未确认的模型能力声明。
